# Football Manager ODD（FMODD）
FMODD is an unofficial Windows desktop companion for Football Manager. This repository publishes the current V2.7.0beta application source without importing the private development history.

- 官网与现有安装包：[fmodd.com/download](https://fmodd.com/download)
- 贡献方式：[CONTRIBUTING.md](../CONTRIBUTING.md)
- 第三方材料：[THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)

公开源码快照包含现有程序功能、运行资源和相关测试；个人数据、内部原始研究产物、编译产物和 SDK 二进制不在仓库中。此快照未重新打包 EXE；源码存在及模拟测试不代表所有游戏版本已完成实机验收。

FMODD 是面向 Football Manager 的本地桌面工具。当前版本为 **V2.7.0beta**，由 Python 本地服务、HTML/CSS/JavaScript 界面和 WebView2 桌面宿主组成。

设置中提供手动检查更新，可比较当前软件版本与 FMODD 官网发布版本，并在发现新版时前往官网下载页面。

本文是当前产品与开发入口概览。文档的用途、权威边界和推荐阅读顺序见 [`docs/README.md`](../docs/README.md)；历史更新与研究记录不能单独作为当前支持状态的依据。

- Football Manager 26 XGP `0.9.9957.0`：使用 `game_plugin.dll` 的 PE 身份识别，并动态解析 RTTI、游戏日期和存档根；FM26 Hook 仅在特征码唯一命中时启用。当前为 Beta 适配。
- Football Manager 2024 Steam `24.4.2+2081827`：已支持日期、赛程、历史赛果、赔率、人类经理与执教球队、阵容 CA/PA/位置/可见属性、职员名单与合同、转会预算读写，以及已收购俱乐部间的球员转会与租借。单独执教国家队时，连接阶段会从人物附加合同中的国家队合同恢复任职，不再误判为无业；当前英格兰国家队存档已完成只读实机验证。青年队租借仍需完成真实保存、退出和重载验收；当前赛季旧场次也可能显示在新俱乐部名下。详细赛果来自原生 `sicomps::FIXTURE_RESULT`，未观看而直接模拟的比赛由持久 `db::SCORELINE::BASIC_SCORELINE` 补齐，并按存档继续持久保留。

- Football Manager 2024 Epic `24.4.2+2081827`：使用独立 EXE SHA256 识别，平台不同的黑哨 Hook 使用独立 RVA。2026-09-09 已在精确 Epic SHA256 `33E8…5378` 上只读验证数据库/经理根、赛程池、Team Type、PreviousClub、球场 vtable、Club Culture 构造链及四个青训 Hook 入口；这些已验证字段和功能门控现与 Steam 24.4.2 对齐。合作俱乐部新增仍不复用 Steam 固定地址，而是动态唯一解析原生创建入口及管理器调用链；Steam 专用高层转会入口继续关闭并使用现有 Epic 兼容事务。真实写入、Hook 安装、推进日期与保存重载尚未在本轮执行。
- Football Manager 2024 XGP：使用受保护 `fm.exe` 的内存 PE 时间戳与映像大小识别，核心 RTTI、日期及 Hook RVA 已完成首轮映射；比赛会话全局指针在首次使用时按已验证 vtable 动态定位。当前为 Beta 适配。
- FM2024 通过已验证的本地存档提供器读取当前存档名，并使用名称哈希隔离钱包、注单、赛果和设置数据；游戏在同一生涯中因更换执教俱乐部而自动改名时，会结合已确认的人类经理 UID 沿用原存档账户，再更新当前俱乐部和显示名称；另存为不同名称且经理证据不匹配时才检测为新的存档作用域。

- 商店“病毒包裹”会在生效时重新按 Team UID 与 Player UID 定位无伤的对手一线队球员，并创建一条指向 FM 原生“病毒感染”定义、持续 3 天的 `db::INJURY` 记录。2026-09-10 已分别在 FM24 Epic `24.4.2+2081827` 和 FM26 Steam `26.3.2+2329565` 完成单球员即时写入、独立只读会话回读及游戏界面确认；两次实验均未保存或推进日期，因此保存重载、跨日生命周期和到期自动康复仍未验证。
- 球员显示名默认会在内部按稳定 UID 自动匹配当前游戏安装目录中已安装的 `.lnc` 中文人名修订；封装版同时内置由 FM24/FM26 人员汉化 XML 合并生成的 UID 字典。设置→显示中关闭“球员汉化”后，改为显示“姓, 名”，并优先使用 FM 的常用名作为较短姓氏；重新开启即可恢复昵称/字典补全。UID/完整姓名未命中时，先使用无歧义的英文姓名片段拼接和内置精确全名模板，最后对仍为拉丁字母的姓名使用内置、无依赖的保守音译兜底（支持多段、前缀和连字符）。日籍球员是例外：仅采用 UID、完整姓名或可同时确定名和姓的汉字映射，并按“姓＋名”显示且不加中点；汉字不确定时保留游戏原名，不生成西式中文音译。所有音译结果都只是显示用推测，不覆盖任何 UID/XML 正式译名；开发版或未命中的封装条目还会读取用户文档目录中的 `数据库人员汉化.xml` 作为后备字典。无需用户导入或配置，用户手工名称仍优先。

- FM26 Steam `26.3.2+2329565` 的董事会目标新增已改为在游戏逻辑线程调用原生 `Club Culture` 构造器，只覆盖已验证业务字段后再加入愿景 vector；柏太阳神新增普通目标已完成保存、重载和稳定球队 UID 回读。FM24 Steam `24.4.2+2081827` 使用独立原生构造器及初始化入口，当前完成静态调用链与自动化验证，仍待新的保存重载实机验收。FM24 Epic/XGP 与 FM26 XGP 不套用 Steam RVA，新增入口保持关闭。FM26 现有目标的原位修改及 `BasicFinances.SugarDaddy` 的标量写入另有账户作用域回放保护：若游戏重建对象后未从存档恢复目标值，FMODD 会按稳定 UID/目标业务字段重新校验并补写；这属于 FMODD 恢复层，不等同于证明 FM 原生存档已经序列化该字段。

- 开发版另有独立的 8F“关系综训楼”，不复用或改变 7F 普通训练定义。修心室、传习室、战术指导室、视频分析室和运动科学室均按游戏日积累专项点与双向亲密度；新关系分别按队友、爱徒/教练组职员、朋友类别建立，既有关系保留原类别并只增长数值。视频分析要求数据分析达到 15 的表现分析师，运动科学要求运动科学岗位职员并排除伤员。运动科学结算同时按团队能力恢复疲劳、比赛状态和体能，并在年龄、概率和初始身高上限内处理身高。人物关系网提供沉浸式双向关系对照，以及覆盖训练、活动中心、心理辅导等实际写入事件的关系变化时间线；时间线保留中文事件来源和双方事件角色，按球员/职员分类可即时展开或收起。训练档案按指导者/被指导者分层，逐条保留实际器材或房间及训练内容，并提供独立弹窗式关系档案摘要。永久厌恶统一显示为 `💀`。全部原生字段执行身份复验、写后回读和失败回滚，账户进度、房间释放及训练档案在同一账户事务提交。8F 原生结算仍受开发版门禁控制，正式冻结运行时不会开放写入。
- 活动中心 2F“人员谈话室”新增“球员离队”：在自有俱乐部及其一线、预备、青年梯队中选择球员，点击寻找买家取得最多五家外部俱乐部的模拟报价。同类买家可以重复，报价不低于有效身价或 ODD 估值；接受后执行原生转会并把款项记入卖方俱乐部结余，拒绝不补报价。本轮保留七个游戏日，成交受现有版本门禁控制。
- 活动中心 5F 为“情报中心”，一次性解锁价格为 £50M。页面恢复情报室场景图，并在场景上方提供“获取随机比赛情报”“获取指定比赛情报”“已获取比赛情报”三个入口。随机入口可分别购买胜负、总进球数或比分情报，付款后由服务端从尚未获取该类情报的比赛中随机揭晓一场；指定入口通过赛事与比赛两级选择卡购买；已获取入口按购买游戏日期分成“今天已获取”和“之前已获取”，比赛离开当前获取窗口后仍保留历史结果，旧存档中没有购买游戏日期的记录归入之前已获取。它只提供普通战绩页因尚未开赛而隐藏、同时又能与当前已发布盘口按日期、赛事及主客队精确匹配的原生赛果情报；公开列表、随机选择和购买提交都会重新与当前盘口取交集，盘口中已不存在的比赛不能再获取。可售场次必须位于当前游戏时间或之后，开球分钟仍可购买，时间越过开球分钟后立即停止展示与售卖。当天第一次进入情报中心时锁定定价基准：存在有效单关投注上限时，以该上限与当日观察到的银行及钱包最高合计资金中的较低者为基数；明确设置为无上限时，以当日观察到的银行及钱包最高合计资金为基数。余额增加时基数最多上调至单关上限，余额减少时当日价格不下调；随机购买的胜负、总进球数、比分情报分别按 35%、35%、85% 定价，指定购买分别按 40%、40%、88% 定价，所有模式均不设置固定最低价。获取或重启不会降低当日基准。获取比分情报后同时解锁前两项，不显示进球球员或事件。未获取的赛果字段不会进入公开状态、盘口快照、结算、积分榜或 ELO。
- 情报中心在最终投注结算时会复核已售胜负、总进球数和比分选项；若与已验证最终比分不一致，按原银行/钱包付款分账自动退款并发送站内邮件。退款可安全重复执行，不改变投注本身的输赢和派彩。
- 执教合同工资按游戏日逐日累计 30% 税率后的金额，固定于每周日存入 FMODD 银行；每次实际付款分别投递一封按付款 ID 去重的工资到账邮件。已收购俱乐部上月利润的 5% 仍在当月 1 日幂等结算并发送分红到账邮件；跨日、跨周或跨月跳转会补结，不会重复入账或重复发信。
- 已收购俱乐部可通过 ODD 模拟招商寻找赞助：报价为同联赛全部俱乐部结余平均值的 1/4，最多收到 3 份虚拟行业意向；邮件中可继续寻找或接受，接受后年度赞助费写入目标俱乐部 FM 结余，不写球衣或 FM 原生赞助表。该功能仍需在确认前备份存档。
- 银行页提供银行与投注钱包合并的统一账本，支持按月份、账户、类别、收支方向与关键字筛选并分页查看；内部转账单列显示，不计入收入、支出或净变化。

## 数据边界

- 每个 FMODD 账户保存为 `saves/<账户>.fmodd` 单文件；钱包、投注、物品、设施与其他账户状态不会再散落为多个业务文件。读改写由跨进程互斥锁串行化，写入使用唯一临时文件、落盘刷新和原子替换，不再新建面向用户的 `.fmodd.backup` 副本。历史 backup 仍可在主文件损坏且通过作用域与 schema 校验时恢复；高于当前程序支持版本的容器拒绝降级写入。
- 正式版启动时会比较上次观察到的 FMODD 应用版本；检测到新版本后，向当时已经存在的每个账户投递一封永久保留、可手动领取 50M 的“更新奖励”邮件，领取前不会自动入账。领取通过账户容器事务完成，重复点击或请求重试不会重复加钱。尾部字母构建共享数字主版本奖励，例如 `2.2.0b`、`2.2.0c`、`2.2.0d` 均按 `2.2.0` 处理，不重复投递；处理失败的账户会在后续启动时重试，本版本内后来新建的账户不补发。
- 投注历史始终显示全部未结算注单，并最多显示最新 500 条已结算注单；更早的记录不进入历史列表，但仍保留在账户数据中供收益分析和人工清理使用。
- 盘口、模型和世界俱乐部派生快照保存在独立的 `cache/` 目录。赛果历史属于按生涯隔离的结算证据，保存在 gzip 压缩的 `careers/<生涯>/result_history.json`；旧明文账本继续兼容读取并在下次整理时原位压缩。正式运行数据按 100 MiB 稳态预算管理：启动及大型账本/盘口写入后优先清理遗留临时文件和可重建缓存，必要时淘汰赛果备份，但不删除 `.fmodd` 账户真值或赛果主账本。旧 `cache/<作用域>/results/fm26_result_history.json` 会在新账本首次成功保存前兼容读取，合并写入并记录已导入后不再反复带回过期旧记录。
- 旧版账户目录会在首次打开时无损迁移。设置中的“清除缓存”不会删除 `.fmodd` 账户存档、`careers/` 结算账本或 Football Manager 的 `.fm` 文件；它仍会保留当前账户待结算注单引用的盘口快照，清理后保留已验证的存档/账户身份并在新线程中完整重建派生数据。未绑定账户时拒绝使用 `unidentified` 持久化或缓存路径。
- 设置中的“删除当前存档”需要连续两次确认，只重置当前 `.fmodd` 账户数据并保留存档/经理身份；不会删除其他账户、`careers/` 结算账本或 Football Manager 的 `.fm` 游戏存档。

- 开发版运行数据、FM 扫描结果和研究资料位于 `data/`，不进入 Git。
- 正式版用户数据默认位于用户“文档/FMODD”目录，不属于项目源码。
- 存档身份映射保存在 `context_registry.v2.json`。首次升级只认领已有数据目录，不移动或改写 `.fm` 游戏存档；若存在旧 `save_registry.json`，会先保留 `save_registry.v1.backup.json`。
- 每个 FM 生涯使用永久 `career-*` 身份，每个“生涯＋人类经理”使用永久 `account-*` 身份。经理 UID 用于确定生涯内账户；FM24 首次只读到经理而暂缺稳定存档证据时建立的临时生涯，会在同一活动上下文随后取得稳定证据时原地升级并保留原账户、钱包和库存，不再创建空账户。两个各自具备不同稳定证据的存档仍不会仅因经理 UID 相同而合并。账户首次完整识别经理与执教球队后，显示名称固定为“经理名-执教球队名-经理ID-首次识别日期”；该名称不参与物理路径或账户匹配，换队也不会重命名。设置中的历史账户选择可临时切回旧数据账户，也可恢复“跟随自动识别”。
- 生涯共享人物库容器不会进入“存档账户”列表，也不能被恢复成钱包账户；旧版基础名称 `.fmodd` 仍可在首次经理绑定时无损认领。FM24 后台先复核已确认经理对象，换队或经理列表变化不会切档；对象失效后再用本地存档名或无重叠的人类经理 UID 集合确认真正换档。保留相同经理 UID 的网络存档副本仍需使用“更换存档刷新”。
- 设置→存档账户提供“合并同ID账户”：仅在当前 FM 代际内，将相同经理 UID 的多个账户文档去重合并到一个新账户并绑定当前生涯；源账户和原始容器保留为备份，盘口/模型缓存不直接拼接，合并后按当前存档重新验证。
- 正式资源位于 `web/assets/` 和 `assets/`。
- `assets/source/` 保存原始美术素材；程序实际使用压缩后的 `web/assets/`。
- 退役计划交流支持在“本俱乐部 / 全世界”范围间切换，并提供球员或球队搜索；全世界候选直接来自当前 FM 原生退役管理器与 Person 目录的交集，避免逐人扫描。
- 训练器材目录载入时会清理已退役器材及仍在使用的关联任务，但保留历史会话档案；历史记录继续通过旧 SKU 显示当时的器材名称。
