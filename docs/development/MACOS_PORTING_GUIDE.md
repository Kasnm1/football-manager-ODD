# FMODD macOS 功能与移植说明

> 文档状态：移植规划，不代表 macOS 已受支持。
>
> 当前基线：FMODD V2.6.9 的正式运行环境仍是 Windows。本文用于划分可复用能力、平台替换点、研究证据和验收边界，不授权操作真实 FM 进程、写入存档或发布 macOS 安装包。

## 1. 移植目标与基本原则

macOS 版本的目标应是复用 FMODD 已有的 Web UI、HTTP API、账户与领域逻辑，同时用独立的平台层替换 Windows 桌面宿主、进程发现、模块识别、内存访问、原生库、Hook 和封装流程。

移植不是把 Windows 可执行文件换一种方式打包。以下结论必须始终分开：

- 业务语义可通用，不代表内存地址、字段布局或原生调用可通用。
- Python 模块可导入，不代表其中的 Windows 原生路径在 macOS 可执行。
- Windows 上已经验证的 FM24/FM26 能力，不代表对应 macOS build 已验证。
- Intel Mac、Apple Silicon 原生运行和 Rosetta 2 运行是不同目标身份，不能共享未经验证的地址与 Hook。
- 首版应先做到离线界面和只读连接，再逐步开放写入；Hook 最后处理。

## 2. 当前功能清单与移植判断

状态说明：

- **可复用**：核心实现以 Python、HTML/CSS/JavaScript 或平台无关数据为主，但仍需在 macOS 跑测试。
- **需平台适配**：业务逻辑可保留，入口、路径、权限或底层实现必须替换。
- **需重新研究**：依赖 FM 进程内部结构，必须针对精确 macOS build 重新取证。
- **首版关闭**：风险或工作量高，不应成为首个 macOS 可用版本的阻塞项。

| 功能领域 | 当前能力 | macOS 判断 | 说明 |
| --- | --- | --- | --- |
| Web UI 与多语言 | 页面、主题、交互、11 个界面语言、可访问性状态 | 可复用 | 继续由本地 HTTP 服务提供；需验证 Safari/WKWebView 的 CSS、字体、下载和剪贴板行为。 |
| 本地 HTTP/API | `/api/*`、公共状态、错误模型、后台协调 | 可复用 | 必须继续只绑定回环地址，并保留关闭、超时和并发契约。 |
| 设置与账户容器 | 经理账户、钱包、库存、通知、设施、缓存迁移 | 需平台适配 | JSON/事务逻辑可复用；数据目录、跨进程锁、权限和迁移路径要改为 macOS 语义。 |
| 投注账户与结算 | 注单、钱包、退款、派彩、风控、账本 | 可复用 | 业务逻辑可复用，但盘口、比赛身份和赛果仍依赖可信 FM 数据源。没有可信赛果时不得结算。 |
| 赔率与冠军盘 | 概率模型、盘口生成、ELO、冠军盘、收益分析 | 可复用 + 需数据适配 | 数学与展示可复用；赛程、球队、阵容、日期和赛果读取必须来自 macOS 已验证读取器。 |
| 更新检查与官网 | 版本比较、下载页、静态官网 | 可复用 | macOS 产物必须有独立平台标识、下载地址、摘要和兼容矩阵，不能复用 Windows EXE 信息。 |
| 存档/经理/球队识别 | 当前存档、人类经理、执教球队、账户作用域 | 需重新研究 | 当前链路依赖 Windows 进程与已验证布局；macOS 必须重新定位对象根、合同和存档身份。 |
| 赛程、赛果与积分榜 | 赛程池、短期/持久赛果、积分榜、比赛事件 | 需重新研究 | Mach-O build 下的 RTTI、对象池、容器和事件结构必须重新验证。 |
| 球员与职员读取 | UID、姓名、合同、CA/PA、属性、状态、关系等 | 需重新研究 | 字段语义可能相同，但偏移、vtable、对象生命周期和模块基址不能沿用 Windows。 |
| 俱乐部与国家详情 | 财政、设施、阵容、职员、国家和赛事资料 | 需重新研究 | UI 和投影可复用；所有原生字段需要 macOS `GameLayout` 能力门禁。 |
| 名人堂与历史转会 | 人物库、观察快照、最佳阵容、转会投影 | 部分可复用 | 账户侧档案和 UI 可复用；原生转会归档、历史统计与头像路径要分别适配。 |
| 球员头像与名称本地化 | graphics XML、UID 映射、中文显示 | 需平台适配 | 解析逻辑可复用；FM 安装目录、用户数据目录、路径大小写和文件授权需适配。 |
| 经营与经济操作 | 收购、赞助、预算、合同工资、俱乐部转账 | 部分可复用 | 报价、账户事务和 UI 可复用；任何 FM 内存读写都必须等待 macOS 精确布局和事务验证。 |
| 球员/职员编辑 | 属性、CA/PA、位置、语言、关系、转会、租借 | 需重新研究 | 属于真实内存写入；必须具备旧值校验、写后回读、失败回滚和对象身份复验。 |
| 训练场与活动中心 | 设施、任务、训练档案、冷却和账户进度 | 部分可复用 | 账户侧规则可复用；实际人物属性、伤病、关系或状态结算依赖 macOS 写入层。 |
| 青训与退役 | 青训计划、候选名单、不退役能力 | 需重新研究 | 读取名单可先做；原生生成与不退役 Hook 首版关闭。 |
| 比赛道具与裁判能力 | 兴奋剂、买通门将、病毒、功能饮料、黑哨等 | 首版关闭 | 高度依赖远程内存、原生分配器、代码补丁和 Hook，不可复用 Windows RVA/AOB。 |
| 桌面窗口 | WebView2、窗口状态、外部链接、生命周期 | 需平台替换 | `net48` WinForms/WebView2 不能移植；建议使用原生 WKWebView 宿主或成熟的跨平台 WebView 框架。 |
| 正式封装与保护 | PyInstaller、Cython、Rust DLL、C++ Hook DLL、完整性校验 | 需平台替换 | macOS 需要 `.app`、Mach-O 动态库、签名、公证和独立完整性清单。 |

## 3. 推荐的首版范围

### 3.1 macOS Alpha 0：离线桌面壳

- 启动本地服务并显示 Web UI。
- 设置、多语言、主题、账户容器和不依赖 FM 的档案页面可用。
- 支持正常退出、单实例、日志和数据目录选择。
- 所有需要 FM 连接的操作显示明确的“macOS 暂未验证”，不静默失败。
- 不申请进程控制权限，不读写 FM，不安装 Hook。

### 3.2 macOS Alpha 1：只读连接

- 识别精确 FM 版本、发行渠道、进程架构和模块 UUID。
- 读取游戏日期、存档、经理和执教球队。
- 在独立 `GameLayout` 下逐项开放赛程、赛果、球队、球员和职员读取。
- 只读失败仅关闭对应能力，不回退到 Windows 地址或其他 macOS build。

### 3.3 macOS Beta：业务闭环

- 在只读证据稳定后开放盘口、投注和结算。
- 先开放账户侧功能，再开放少量具有完整回滚能力的标量写入。
- 每项写入都要在 Intel/Apple Silicon 的目标运行方式上独立验收。
- Hook、远程原生调用和代码页修改仍默认关闭。

### 3.4 后续版本：高风险原生能力

- 远程分配、原生构造器调用、伤病容器、转会事务。
- 青训、退役、比赛引擎和裁判类 Hook。
- 只有在安装、运行、卸载和崩溃恢复都可验证时才进入公开版本。

## 4. 平台替换设计

### 4.1 建议新增平台边界

不要在现有业务模块中到处增加 `if sys.platform == "darwin"`。建议把平台差异收敛为以下接口，再让现有服务依赖接口：

| 平台接口 | Windows 当前来源 | macOS 实现目标 |
| --- | --- | --- |
| `DesktopHost` | `fmodd_desktop.py`、`desktop/WebViewHost.cs` | `.app` 宿主、WKWebView、窗口状态和外部链接策略 |
| `ProcessDiscovery` | Toolhelp/Win32 进程与模块枚举 | `libproc`/受支持系统 API，返回 PID、架构、路径和模块身份 |
| `ProcessMemory` | `OpenProcess`、`ReadProcessMemory`、`WriteProcessMemory` | Mach task 与 `mach_vm_*` 封装，统一错误和权限状态 |
| `ModuleIdentity` | PE 时间戳、映像大小、SHA-256、DLL | Mach-O UUID、代码签名身份、文件摘要、加载映像与架构 |
| `NativeRuntime` | Rust/C++ DLL | 按架构构建的 `.dylib` 或宿主内静态库 |
| `StoragePaths` | `%LOCALAPPDATA%`、Documents | Application Support、Caches、Logs 和用户选择的数据目录 |
| `StorageLock` | Windows named mutex | `flock`/文件锁或等价的跨进程锁 |
| `GameLayoutResolver` | Windows EXE/DLL 身份与布局 | macOS build、架构、Mach-O 映像身份和独立能力表 |

业务模块不得直接假设句柄类型、模块后缀、PE 结构、页面保护常量或 Windows 路径。

### 4.2 桌面宿主

当前 `desktop/WebViewHost.csproj` 是 `net48` WinForms，使用 WebView2、`user32.dll` 和 `dwmapi.dll`，必须整体替换。可选方案：

1. 原生 Swift/SwiftUI + WKWebView：平台一致性和签名流程最好，但需要维护一个新的宿主项目。
2. 成熟的跨平台 WebView 宿主：开发较快，但要核对 WKWebView 生命周期、下载、外链、窗口恢复和分发许可。
3. 首期使用系统浏览器：最容易验证后端，但只适合作为开发入口，不应冒充正式桌面体验。

无论选择哪种方案，都必须复用同一个本地运行时启动/关闭契约，限制导航到本地源和明确允许的外部地址，并在窗口退出时可靠停止后台任务。

### 4.3 进程与内存访问

Windows 的 `OpenProcess`、`VirtualQueryEx`、`ReadProcessMemory`、`WriteProcessMemory`、`VirtualAllocEx`、`CreateRemoteThread` 和 DLL 模块枚举在 macOS 不存在。macOS 读取器至少需要：

- 发现 Football Manager 进程、可执行路径和实际运行架构。
- 获取目标 task，并把“未授权、目标受保护、进程已退出、架构不匹配”区分为稳定错误码。
- 枚举 Mach-O 映像、ASLR slide、UUID、代码段和数据段。
- 读取虚拟内存区域并校验映射权限、对象地址和当前会话 generation。
- 写入前验证期望旧值，写入后回读；失败时恢复原值。
- 进程重启、存档重载或模块变化后立即废弃所有地址和缓存。

不得要求用户关闭 SIP，也不得把以 root 运行作为常规解决方案。若目标进程的签名、Hardened Runtime 或系统策略阻止访问，应明确报告能力不可用并停止，而不是绕过系统安全机制。

### 4.4 GameLayout 与二进制身份

macOS 必须新增独立的布局集合，至少把以下维度纳入键：

- FM24 / FM26 代际。
- 精确游戏 build。
- Steam 等发行渠道。
- `x86_64`、`arm64`，以及 Apple Silicon 上经 Rosetta 运行的 `x86_64`。
- 主 Mach-O 与关键映像的 UUID、文件摘要和实际加载身份。

Windows 的 EXE SHA-256、PE timestamp、RVA、DLL 名称、vtable、AOB 和 Hook 字节只可作为研究线索，不能直接写入 macOS 布局。即使类名或字段语义相同，也必须重新证明对象起点、偏移、容器布局、指针宽度、对齐和调用约定。

### 4.5 原生核心与 Hook

`native/fmodd_native_core` 当前仅在 Windows 下链接 `kernel32`，`native/fmodd_hook_core` 直接包含 `windows.h`。移植时应把纯数学、纯布局校验与进程 I/O 拆开：

- 纯数学和纯字节校验可编译为跨平台 Rust/Cython 核心。
- 进程读写通过平台接口注入，不让纯核心链接系统进程 API。
- macOS 原生库按 `arm64` 与 `x86_64` 分别构建，确认后再决定是否合并为 universal binary。
- 不把 `.dll` 路径、Windows 文件锁或 PyInstaller `_MEIPASS` 规则原样带入 macOS。
- Hook 必须有独立的安装前签名校验、原字节保存、卸载恢复和崩溃恢复设计。

首版不实现代码注入、远程线程或可执行页补丁。App Store 沙箱通常与跨进程内存能力冲突，分发路线应优先评估开发者签名并公证的站外 `.app`。

### 4.6 数据目录与锁

建议默认路径：

- 持久数据：`~/Library/Application Support/FMODD/`
- 缓存：`~/Library/Caches/FMODD/`
- 日志：`~/Library/Logs/FMODD/`
- 用户主动选择的外置数据目录：保存 security-scoped bookmark 或宿主框架的等价授权凭据。

现有 `tools/app_paths.py` 在冻结版使用 Windows 配置目录和 Documents 默认目录，需要平台化。`tools/storage_io.py` 在非 Windows 上目前只有线程内锁，不具备多个进程之间的互斥保证；macOS 版本必须增加跨进程文件锁，并验证原子替换、崩溃残留、外置卷断开和大小写敏感文件系统。

不得自动扫描、上传或迁移用户的 Windows `data/`。如支持跨平台迁移，应只迁移去地址化的账户/生涯数据，并先验证格式版本、备份、冲突处理和回滚。

## 5. macOS 权限与分发注意事项

- 使用 Developer ID 对 `.app`、嵌入式 Python、Mach-O 库和辅助程序逐层签名。
- 完成 Hardened Runtime 配置和 Apple notarization，再验证 Gatekeeper 首次启动。
- 只申请实际需要的 entitlement；不要为了方便申请宽泛文件或系统权限。
- 不默认请求辅助功能、完全磁盘访问或管理员权限。确有必要时，要解释用途和撤销路径。
- 明确区分“应用可启动”和“可读取 FM 进程”两种状态，权限失败不能导致账户数据损坏。
- 安装包应提供 SHA-256；自动更新必须区分 `windows-x64`、`macos-x64` 和 `macos-arm64`。
- 官网与更新 API 不能让 macOS 客户端下载 Windows EXE。
- 正式版不得包含源码、调试符号、本机绝对路径、研究样本、存档、账户数据或内存转储。

## 6. 必须先采集的目标机证据

开始内存适配前，至少需要一台目标 Mac 完成只读采集。每个目标组合记录：

- macOS 版本、Mac 型号和 CPU 架构。
- FM 版本、精确 build、发行渠道和实际进程架构。
- FM 主程序路径、主 Mach-O UUID、SHA-256、代码签名信息。
- 关键加载映像名称、UUID、ASLR slide 和地址范围。
- FM 是否经 Rosetta 2 运行。
- 启动游戏、进入存档、切换存档和退出后的进程/映像生命周期。
- 只读 task 获取结果及原始系统错误；不要先尝试写入或注入。

采集工具应默认脱敏，不收集存档正文、账户文件、个人路径、完整内存转储或无关进程。任何需要降低系统安全设置的方案都应停止并重新设计。

## 7. 验证矩阵

每项能力都要在声明支持的组合上单独验收：

| 层级 | 最低检查 |
| --- | --- |
| 纯业务 | 现有单元测试在 macOS 通过；时间、路径和文件锁测试不依赖 Windows 假设。 |
| Web UI | WKWebView/Safari 下主要页面、主题、多语言、焦点、键盘、最小字号和错误状态正常。 |
| 桌面宿主 | 启动、单实例、窗口恢复、外链、异常提示和退出清理正常。 |
| 只读连接 | 精确 build/架构识别；日期、存档、经理和球队与游戏界面一致。 |
| 对象读取 | UID、vtable/类型、反向引用、范围和会话失效均有负向测试。 |
| 内存写入 | 旧值校验、写后回读、失败回滚、进程退出和存档切换全部验证。 |
| Hook | 安装前原字节、唯一签名、卸载恢复、重复启停、崩溃恢复和版本拒绝均验证。 |
| 持久化 | Application Support、外置卷、并发实例、断电式中断和旧数据迁移验证。 |
| 分发 | Intel/Apple Silicon 目标安装、签名、公证、Gatekeeper、升级和卸载验证。 |

静态测试、模拟内存和 Windows 实机结果都不能替代目标 macOS build 的实机证据。对外兼容表只列出已完成上述门禁的组合。

## 8. 建议实施顺序

1. 建立 macOS CI，先让纯 Python、前端和账户测试在 macOS 通过。
2. 抽出平台接口，消除入口层和业务层对 Win32 类型的直接依赖。
3. 实现数据目录、跨进程锁和 macOS 桌面宿主。
4. 交付不连接 FM 的 Alpha 0，验证安装、UI、账户和退出链路。
5. 开发只读诊断器，采集精确 build、架构和 Mach-O 身份。
6. 实现只读 `ProcessMemory` 与 macOS `GameLayoutResolver`。
7. 依次验收日期、存档/经理、赛程/赛果、球队、球员和职员。
8. 接回赔率、投注与结算，验证所有事实来源和账户作用域。
9. 只开放具有完整事务与回滚证据的写入功能。
10. 最后评估 Hook；无法满足安全卸载和版本拒绝时继续保持关闭。

## 9. 不应做的事情

- 不把 Windows RVA、AOB、偏移或 DLL 名改成 Mach-O 名后直接使用。
- 不用“页面能打开”宣称某项 FM 读取或写入已支持。
- 不要求用户关闭 SIP、长期使用 root 或执行未知注入脚本。
- 不在权限失败时回退到未验证布局。
- 不跨会话持久化 FM 地址，不把旧地址当作缓存优化。
- 不用合成测试代替真实 macOS build、保存重载或退出恢复验收。
- 不在尚无稳定版产物时更新官网为“macOS 已支持”。

## 10. 完成定义

只有同时满足以下条件，某个 macOS 版本才可对外标为受支持：

- 精确 macOS、FM build、渠道和架构身份已记录。
- 安装包已签名、公证并通过干净机器 Gatekeeper 验证。
- 声明开放的每项读取/写入能力均有目标机证据和负向门禁。
- 账户、缓存、日志和升级路径不会覆盖 Windows 数据或真实存档。
- 不支持的 Hook/写入在 UI、API 和后端三层均失败关闭。
- 官网、更新清单、下载文件、SHA-256 和兼容矩阵一致。
- 已记录尚未验证的保存重载、跨日行为或其他证据缺口。

在达到上述条件前，产品文案应使用“macOS 移植中”或“目标 build 未验证”，不能写成已完整支持。
