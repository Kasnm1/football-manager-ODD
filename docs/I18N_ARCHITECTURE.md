# FMODD 界面国际化架构

> 状态：当前实施契约
> 范围：FMODD 自有的 Web/WebView 界面、API 用户消息、站内邮件与桌面宿主提示

## 1. 目标与完成边界

FMODD 以 `en-GB` 为默认和权威回退语言，完整迁移目标为 `en-GB`、`zh-CN`、`zh-TW`、`ko-KR`、`de-DE`、`es-ES`、`fr-FR`、`ru-RU`、`ja-JP`、`pt-BR` 与 `pt-PT`。语言是全局应用偏好，不绑定存档、经理或账户。

“完整语言版本”指 FMODD 自己控制的可见文字均来自稳定语义键，包括页面标题、导航、按钮、表头、表单、加载/空/错/忙状态、Toast、确认弹窗、操作记录、站内邮件和桌面宿主提示。下列内容保持事实原文，不做通用翻译：

- 球员、职员、球队、赛事、球场和存档中的原始名称；
- 用户自定义集团名、房间名、阵型名和备注；
- 旧版本只保存了最终正文、无法可靠恢复语义参数的历史记录；
- Windows 提供且应用无法控制的系统级文字。

商店的页面结构、分类、筛选、购买动作、金额、确认、反馈，以及 FMODD 自有物品的名称、描述、等级和效果提示均必须本地化。物品以稳定 SKU 识别，翻译仅影响展示，不写入存档；当前没有独立剧情或世界观字段，今后若新增也必须使用稳定语义键。玩家、球队、赛事等游戏事实仍按上方边界保留原文。

完成不能以“语言入口存在”或“词典数量一致”代替。每个语言必须通过缺键、参数、可见残留文字、布局和关键交互验收。

## 2. 权威与回退

1. `en-GB` 是新文案的权威含义和缺失翻译回退。
2. `zh-CN` 与 `ko-KR` 继续在领域模块内保持与英文相同的语义键及参数集合；台湾繁体中文、德语、西语、法语、俄语、日语、巴西葡萄牙语和欧洲葡萄牙语由独立语言包覆盖同一英文键集合及参数集合。
3. 新代码不得用中文正文作为长期键，也不得依赖模糊字符串替换。
4. 现有 `legacyEnglish`/`legacy` 精确映射仅承担迁移兼容；对应模块完成语义键迁移后移除其旧条目。
5. 缺少目标语言键时显示英文并记录审计缺口；不得静默显示中文，也不得隐藏操作。

目录键使用 `domain.surface.element.state`，例如：

```text
settings.display.language.label
betting.slip.place_button
training.plan.status.completed
error.account.insufficient_funds
mail.salary.subject
```

整句翻译，参数只承载名称、数字、日期和金额等事实。不得用多个短词在前端拼接语法句。

## 3. 文案来源边界

| 来源 | 责任 | 迁移方式 |
| --- | --- | --- |
| `src/web/index.html` | 静态结构、标签、ARIA | `data-i18n` 与属性键 |
| `src/web/app.js` | 动态模板、状态、Toast、弹窗 | `uiText(key, params)` / `uiPlural` |
| Python API/领域模块 | 错误码、阶段、可重试与事实参数 | 返回稳定 `error_code`/`message_key`/`message_params` |
| 邮件与操作记录 | 可重放事件 | 保存事件类型、模板版本与参数，阅读时翻译 |
| `src/fmodd_desktop.py`、`src/desktop/WebViewHost.cs` | Web UI 之前的宿主提示 | 宿主内置同键目录或由启动参数传入语言 |

日志、诊断详情与开发异常可以保留技术语言，但不能直接冒充最终用户提示。游戏事实与本地化界面文案必须分字段传递。

API 仍兼容旧业务校验的 `error` 原因，同时用 `message_key` / `message_params` 提供语义化提示。已迁移的专用语义键始终优先显示；只有服务端明确以 `error_detail_safe=true` 标记的既有 `ValueError` / 金额校验原因，前端才用该具体原因替代“请求无效”一类通用占位消息。`TypeError`、`KeyError`、未知运行时异常和未显式标记的领域异常不得走此回退，避免把实现或诊断信息直接暴露为用户提示。

### 3.1 Web 目录装配

`src/web/i18n.js` 只负责 locale 状态、英文回退、参数替换、复数、格式化、DOM 应用与动态节点观察。领域文案按 `src/web/i18n.<domain>.js` 拆分；各文件在核心之前向 `window.FMODDI18nModules` 注册英中韩三种语言的同构目录。`src/web/i18n.ko.js` 是旧过渡目录，领域完成语义键迁移后逐步并入对应模块。

台湾繁体中文、德语、西语、法语、俄语、日语、巴西葡萄牙语和欧洲葡萄牙语分别由 `src/web/i18n.tw.js`、`src/web/i18n.de.js`、`src/web/i18n.es.js`、`src/web/i18n.fr.js`、`src/web/i18n.ru.js`、`src/web/i18n.ja.js`、`src/web/i18n.pt-BR.js` 与 `src/web/i18n.pt-PT.js` 注册到 `window.FMODDLocalePacks`。语言包在全部领域模块之后、核心之前加载，并覆盖同一套英文语义键；缺键由核心明确回退至英文。各语言包可根据领域模块中的中文源值和同键目标译文生成精确 legacy 映射，不复制一份独立的旧中文目录。独立语言包避免为了新增一种语言而重写所有现有三语领域文件。

`zh-TW` 以 `zh-CN` 的稳定语义键为转换基线，但最终目录保存为静态译文，并在字形转换之后应用台湾惯用术语，例如「軟體、資料夾、儲存、載入、設定、快取、搜尋、連線、總教練、守門員、賠率、過關、交易明細、儲值、提領」。不得在运行时逐字替换，也不能让字符转换覆盖球员、球队等事实参数。

语言包只能注册经过逐键或整句审阅的目标文本。不得用通用逐词替换、短语拼接或给英文加语言前缀来伪造完整覆盖；未完成的键必须缺省并接受英文回退，直到整句译文通过术语、语序和占位参数检查。语言选择器中的语言名始终使用自称：`English`、`简体中文`、`繁體中文`、`한국어`、`Deutsch`、`Español`、`Français`、`Русский`、`日本語`、`Português (Brasil)`、`Português (Portugal)`。

静态节点使用 `data-i18n`，属性使用 `data-i18n-aria-label`、`data-i18n-placeholder`、`data-i18n-title` 或 `data-i18n-alt`。动态句子调用 `uiText(key, params)`；运行时 DOM 观察只保证新节点会经过翻译流程，不替代语义键，也不能处理 Canvas 文字。Canvas、图表和 3D 覆盖层必须在绘制前取得翻译后的字符串。

DOM 应用器只可在节点当前内容仍是该语义键的已知静态译文时切换 `data-i18n` 文本；若业务渲染已写入球队名、经理名、数量或组合状态等运行时内容，必须保留该内容，不能用静态默认文案覆盖。

### 3.2 API 消息协商

浏览器请求通过 `X-FMODD-Locale` 传递应用当前语言，服务端仅在缺少该头时参考 `Accept-Language`。错误响应迁移期间保留旧 `error` 字段供诊断与旧客户端使用，同时新增：

```text
error_code      稳定机器码
message_key     稳定语义键
message_params  事实参数
message         当前语言渲染结果
error_phase     失败阶段
retryable       是否适合重试
```

新前端优先显示 `message` 或本地用 `message_key` 渲染，不能把旧 `error` 中的异常详情直接展示给玩家。请求语言只影响文案，不参与账户、存档或业务缓存键。

## 4. 布局契约

- 页面眉题与主标题必须表达不同层级；同一语言中归一化后相同则隐藏眉题，不能显示 `MY GROUP / My Group`。
- 紧凑按钮和菜单项以操作意图为准，而非逐字对齐英文；上下文已明确对象时省略重复名词，例如俱乐部资料行使用 `More / Less`，各语言采用本地自然的短动作词。完整解释保留在标题、帮助或 ARIA 文案中。
- 按钮、页签、工具栏和弹窗操作区按内容伸缩并允许换行，不通过小于 `13px` 的字号容纳译文。
- 表格数字列保持稳定，文字列允许换行或在可发现完整值的前提下省略。
- 德语、西语、法语和俄语长文本必须在真实译文下验收换行；中日韩字体不得裁切上下边缘。
- Toast 允许换行并根据长度延长显示；风险、写入失败和结果未确认还必须进入持久状态或操作记录。
- 语言切换不得刷新页面、清空投注单、覆盖未提交输入、重新发送请求或改变账户/存档状态。

## 5. 迁移顺序

1. 应用外壳、设置、首次提示与全局标题系统；
2. 投注、积分榜、历史、银行、商店与物品栏；
3. 执教管理、世界数据、我的集团、名人堂与关系网；
4. 活动中心、医院、训练场、食堂和全部子弹窗；
5. API 错误、站内邮件、操作记录与桌面宿主；
6. 删除过渡映射并关闭新增裸文案门禁。

迁移旧页面时每一批必须同时补齐英文和韩文；新增台湾繁体中文、德语、西语、法语、俄语、日语、巴西葡萄牙语和欧洲葡萄牙语包时，单个语言文件可以独立推进，但在宣告该语言完成前必须覆盖全部英文语义键，不能把英文回退误报为已翻译。

## 6. 自动化门禁

项目内审计器负责输出候选用户文案的位置、来源类型和中文残留。允许名单必须逐项说明它属于游戏事实、用户输入、内部诊断或历史兼容，不能用整文件忽略。

最低检查包括：

- 英中韩领域目录键集合与占位参数一致；台湾繁体中文、德语、西语、法语、俄语、日语、巴西葡萄牙语和欧洲葡萄牙语语言包覆盖完整英文语义键集合，且占位参数一致；
- 新增用户界面不出现未登记的裸中文或裸英文句子；
- 十一种语言都能完成关键页面的加载、空、错、忙和成功路径；
- 页面标题无同义重复；
- 最小字号、键盘焦点、深色主题与窄窗口布局不回退；
- 内嵌资源包含全部语言目录且离线可用。

静态检查不能证明 WebView 实际字形、换行和焦点体验。最终关闭各语言门之前，需要驾驶员在实际桌面宿主中完成一次最小视觉验收。
